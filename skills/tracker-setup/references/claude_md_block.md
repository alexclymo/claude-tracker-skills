`<!-- END tracker -->`. Read the format stamp with `grep -o 'tracker-format: [0-9]*'`; a block with
no stamp is format 1. This note is documentation for the skills, not part of the block.

## Task System

*`tracker-format: 3`.* Project state lives in `tracker/`, not in this file and not in Claude Code's
in-session task tools, which do not persist. At session start read `tracker/INDEX.md` then
`tracker/PRIORITIES.md`; open a task's `tracker/detail/T###_*.md` when you work on it.

The tracker has one job: what an agent reads at session start must be currently true, and short
enough to be read. Everything below serves that.

- **Correct in place.** A wrong claim is rewritten where it stands, never annotated below or
  contradicted above. Line 3 of each file says how it may be written; write it only that way.
- **Head before body.** A detail file's `## Current state` is rewritten every time its Progress
  log grows, in the same edit. A growing log under a stale head is the failure this system exists
  to prevent.
- **One home per fact.** Status lives in INDEX, what-next in PRIORITIES, narrative in the task's
  Progress log. Point to a fact; do not restate it.
- **Short by construction.** INDEX rows are names, not sentences. PRIORITIES bullets are ≤30 words
  and name a task ID or detail file. Near a cap, move something out before adding.
- **Anchor by name.** Symbols, sections, function names. Never `file:line`.
- **Say where it applies.** A fact true of one model, dataset, or regime carries a tag like
  `[model-B]`.
- **Dead things say so.** A retired approach or task is marked at its home with
  `★ SUPERSEDED by <x> (date)` or status `abandoned`, never deleted and never left reading as
  current. `★` marks nothing else.
- **Decisions live where they were made.** A choice made while working a task is a note in that
  task's detail file. A rule for the whole project goes in `CLAUDE.md` below this block, with the
  human's say-so. Retiring something project-wide is the human's call, never inferred.
- **Stopping criteria before autonomy.** Write success, bailout, and a time cap into the task's
  detail file before working it unsupervised.
- **Do not restructure.** Add no sections to state files and convert no formats mid-task. If this
  block's format number is older than the skill you are running, finish the task as-is and leave a
  one-line note in PRIORITIES for the human.
- **Commit `tracker/` separately from code.**

**Session end.** Run `tracker-close` when the user asks to close, wrap up, or end the session, or
when you are about to stop a long autonomous run. Do not hold state back for close: refresh the
task's detail file as the work moves, so nothing is lost if the session ends without one.
`tracker-audit` is the human's to run; never start it unasked.
